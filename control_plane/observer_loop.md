# Observer Loop

> Версия файла: `v1.0`
> Дата версии: `2026-03-17`
> Тип документа: `watcher concept`

## Что это

Это описание минимального цикла наблюдателя.

Пока его может выполнять человек или отдельный агент-наблюдатель.
Позже этот же цикл может быть реализован как watcher, polling-job или daemon.

## Цикл

1. Прочитать `RUNTIME_STATUS.md` для каждого runtime.
2. Если `status = completed`, прочитать `summary_file` и `evaluation_file`.
3. Сделать post-run вывод:
   - run принят;
   - нужны исправления;
   - нужен comparison;
   - нужна новая mission;
   - нужна эскалация человеку.
4. Записать директиву в `control_plane/<runtime>/OBSERVER_DIRECTIVE.md`.
5. Ждать `RUNTIME_ACK.md`.

## Минимальные реакции observer

### Если runtime завершил run успешно

Обычная реакция:

- `continue_with_next_run`
- или `hold`, если требуется сравнение двух runtime до следующего шага

### Если runtime заблокирован

Обычная реакция:

- `repair_current_state`
- или `human_review_required`

### Если runtime эскалировал проблему

Обычная реакция:

- человек принимает решение;
- затем observer переводит его в формальную директиву.

## Почему это важно

Без observer loop система остаётся полуавтономной:

- runtime умеет работать;
- runtime умеет завершать этап;
- но переход между этапами остаётся неформализованным.

Observer loop формализует именно переход между этапами.
