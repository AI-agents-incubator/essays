# Автономность на уровне ОС: агент живёт вне UI

## Статус документа

Практический инсайт, подтверждённый экспериментом (2026-03-19).
Книжный проект: 48 глав, 48 runs, 0 остановок, 0 вмешательств человека.

## Ключевой инсайт

Агентная организация может и должна работать на уровне операционной системы, а не на уровне UI-приложения.

Это означает:
- Desktop-приложение (Claude Code) — лишь один из способов взаимодействия с агентом, но **не условие его существования**
- Агент может работать когда пользователь спит, приложение закрыто, терминал закрыт
- Единственное условие остановки — явная команда `kill` или завершение задачи

## Механизм

```bash
nohup bash run_agent.sh &
```

Что это делает:
- `nohup` — отвязывает процесс от терминала (переживает закрытие терминала и logout)
- `&` — запускает в фоне (не блокирует текущую сессию)
- Процесс получает PID на уровне macOS/Linux
- Внутри loop вызывает `claude -p` — каждый вызов это отдельный запрос к API
- Desktop app вообще не участвует в цепочке

## Архитектурное следствие

```
UI (Desktop App)     ←→  Человек (наблюдение, управление)
        ↕ (необязательная связь)
OS Process (nohup)   ←→  API (claude -p)
        ↕
File System          ←→  Состояние агента (PROGRESS.md, INBOX.md, коммиты)
```

UI можно убрать из этой схемы — агент продолжит работать. Это фундаментально отличается от модели "агент живёт внутри чата".

## Два типа автономности

| Тип | Где живёт | Зависит от UI | Пример |
|-----|-----------|---------------|--------|
| **Сессионная** | Внутри Claude Code сессии | Да — умирает при закрытии | CronCreate jobs, интерактивный чат |
| **Системная** | На уровне ОС | Нет — полностью независима | nohup процессы, cron ОС, systemd |

Для настоящей автономности нужна **системная** модель. Сессионная — только для мониторинга и управления.

## Масштабирование

Можно запустить N параллельных агентов:

```bash
nohup bash run_agent.sh task_A &   # PID 1001
nohup bash run_agent.sh task_B &   # PID 1002
nohup bash run_agent.sh task_C &   # PID 1003
```

Каждый — независимый OS-процесс. Координация через файловую систему (shared state). Это уже не "один ассистент в чате" — это **организация**.

## Ограничения

1. **Стоимость** — каждый `claude -p` вызов тратит API tokens
2. **Нет real-time связи** — observer видит результаты только при следующем подключении (poll-based)
3. **Crash recovery** — если процесс падает, нужен внешний watchdog (systemd, launchd, cron)
4. **Состояние в файлах** — файловая система = единственный канал коммуникации между агентами

## Следующий шаг

Добавить watchdog: если `run_agent.sh` упал (OOM, network error, API limit), автоматически перезапустить. Варианты:
- macOS `launchd` plist
- Linux `systemd` service
- Простой cron job: `*/5 * * * * pgrep -f run_agent || bash /path/to/run_agent.sh &`
