# Эволюция подхода: от ручного парсинга к параллельной автоматизации

## Контекст

Задача: извлечь транскрипты из 9 курсов Anthropic Academy (Skilljar) для подготовки к сертификации Claude Certified Architect — Foundations (CCA-F). Курсы содержат видеолекции с субтитрами, текстовые уроки и квизы. Итого ~400+ лекций, ~500K символов транскриптов.

---

## Фаза 1: Ручной последовательный парсинг (Курсы 1-8)

### Как это работало

Cowork + Chrome MCP. Для каждой лекции:
1. Навигация к лекции через Chrome extension
2. Клик на кнопку "Transcript" в интерфейсе Skilljar
3. Ожидание загрузки (2-3 секунды)
4. Извлечение текста через `get_page_text`
5. Сохранение в markdown файл
6. Переход к следующей лекции

### Проблемы

- **Строгая последовательность.** Одна лекция за раз. Нельзя обработать следующую, пока не закончена текущая.
- **Transcript panel не переносится между лекциями.** Каждый раз нужно заново активировать.
- **Медленно.** Курс из 20 лекций — ~1-2 часа wall clock time.

Но работало. Курсы 1-8 были извлечены этим методом.

## Фаза 2: Оптимизация через JW CDN (Курс 9)

### Открытие

Skilljar хранит видео через JWPlayer. Каждое видео имеет 8-символьный Media ID. По нему можно получить SRT-субтитры напрямую с CDN: `https://cdn.jwplayer.com/v2/media/{id}` → JSON с URL на SRT файл.

Это означало, что не нужно открывать каждую лекцию и кликать на Transcript — можно скачать все субтитры программно.

### Новый pipeline

1. Batch-запрос HTML всех страниц курса
2. Regex поиск паттерна `botr_{mediaId}_` в HTML
3. Fetch SRT с CDN через `fetch()` в браузере
4. Парсинг SRT → чистый текст
5. Сохранение всего курса как JSON

### Первое столкновение с ограничением sandbox

**CDN JWPlayer заблокирован из sandbox Cowork.** `curl https://cdn.jwplayer.com/...` возвращает exit code 56. Sandbox имеет ограниченный сетевой доступ — это мера безопасности.

**Решение:** Все HTTP-запросы к CDN выполнялись через JavaScript в Chrome (через Chrome MCP), а не из sandbox. Браузер работает на машине пользователя и имеет полный доступ к сети.

## Фаза 3: Проблема передачи данных (Курс 9 — ключевой кризис)

### Ситуация

75 видеолекций, 476K символов транскриптов. Все данные собраны в памяти браузера (`window._savedBatches`). Но их нужно передать на диск sandbox для генерации markdown.

### Фундаментальная проблема

**Между браузером (машина пользователя) и sandbox (виртуальная машина) нет прямого канала.** Все данные должны пройти через контекст модели: браузер → get_page_text → модель → Write tool → диск.

### Попытка 1: Bash heredocs

Идея: записать JSON через `cat <<'EOF' > file.json`.
Результат: символы `\n` в тексте транскриптов ломали JSON. Файл невалиден.

### Попытка 2: Base64 + gzip компрессия

Идея: сжать данные в браузере через CompressionStream API (gzip), закодировать в base64, передать через модель, декодировать на диске.
Результат: base64 строка (~12K символов) проходит через output модели. Даже один изменённый символ = невалидный gzip. Данные систематически повреждались.

### Попытка 3: Chunked transfer через masterJSON

Идея: 476K символов JSON разбить на куски по 30K, передавать через character offset.
Результат: те же проблемы с newlines при пересборке. Corrupted JSON.

### Попытка 4: Агенты

Идея: спавнить агентов (subagents), каждый передаёт несколько batch через get_page_text → Write tool.
Результат: первый агент перепутал индексы batch. Второй попал на лимит output tokens (32K). Третий и четвёртый — частичный успех, но ненадёжно.

### Решение (рабочее)

**document.write() + get_page_text + Write tool:**
1. JavaScript в браузере: `document.write(JSON.stringify(batch))`
2. `get_page_text()` возвращает чистый JSON
3. Write tool сохраняет содержимое as-is (не через bash, без heredoc)

Это работало надёжно, но для каждого batch (~25K символов) требовался полный цикл: JS → read → save. 18 batch = 18 циклов. Два агента обработали по 8 batch каждый — в сумме ~25 минут работы, но ~3 часа wall clock.

### Ключевой урок

Sandbox — это бутылочное горлышко. Любые данные, проходящие через контекст модели, подвержены:
- Ограничению размера (output tokens)
- Потенциальному искажению (base64, специальные символы)
- Последовательности (один batch за раз)

## Фаза 4: Осознание архитектурного тупика

### Масштаб проблемы

Курс 09 (самый большой) занял ~3 часа. Осталось 7 курсов. При последовательном подходе: 7 × 1-3 часа = 7-20 часов.

И это только парсинг. Ещё нужно генерировать summary, обновлять индексы.

### Вопрос пользователя

> "Как запускать тебя параллельно? Могу ли я поднять сотню терминалов?"

Это переломный момент — переход от оптимизации внутри ограничений к преодолению самих ограничений.

## Фаза 5: Смена парадигмы — Playwright вместо Chrome MCP

### Идея

Вместо цепочки "Chrome MCP → модель → sandbox" — использовать Playwright: полноценную браузерную автоматизацию, работающую на машине пользователя.

Playwright:
- Запускает реальный Chromium
- Имеет полный сетевой доступ (JW CDN доступен)
- Сохраняет файлы напрямую на диск (нет передачи через модель)
- Работает headless (без GUI)
- Можно запустить несколько экземпляров параллельно

### Что это меняет

| Аспект | Chrome MCP в Cowork | Playwright на машине |
|--------|---------------------|----------------------|
| Сеть | Заблокирована (sandbox) | Полная |
| Диск | Виртуальный (sandbox) | Реальный |
| Параллелизм | Невозможен | Неограничен |
| Передача данных | Через контекст модели | Напрямую на диск |
| Скорость на 1 курс | 1-3 часа | 10-20 минут |

## Фаза 6: Создание переиспользуемого протокола

### Принцип

Отчуждаемость: всё, что нужно для выполнения задачи, лежит в одной папке. Скопировал → запустил → работает.

### Артефакты

```
protocols/
├── PARALLEL-EXECUTION-ARCHITECTURE.md   ← Теория: 4 стратегии параллелизации
├── CLAUDE-CODE-PARALLEL-GUIDE.md        ← Практика: механика CLI, флаги
└── skilljar-extraction/
    ├── PROTOCOL.md          ← Методика: как устроен Skilljar, JW CDN, SRT
    ├── extract.py           ← Playwright: извлечение данных
    ├── generate.py          ← Python: генерация markdown
    ├── PROMPT-summary.md    ← Промпт для Claude Code: саммари
    ├── KICKSTART.md         ← Копируй-и-вставляй промпт для запуска
    ├── courses.json         ← Конфиг: все 7 курсов
    ├── master-run.sh        ← 7 параллельных Claude Code
    └── run-all.sh           ← 7 параллельных Python (без Claude Code)
```

### Трёхэтапная архитектура

```
Этап 1: extract.py (Playwright)     — параллельно, 7 процессов
        ↓ raw.json на диске
Этап 2: generate.py (чистый Python) — параллельно, 7 процессов
        ↓ markdown файлы на диске
Этап 3: Claude Code (LLM)           — параллельно, 7 экземпляров
        ↓ summary, descriptions
```

## Фаза 7: Открытие возможностей Claude Code CLI

### Ключевой инсайт

Claude Code, работая на машине пользователя (не в sandbox), имеет полный доступ к ОС через bash. Он может запускать любые процессы — включая другие экземпляры самого себя.

```bash
claude -p "задача" --allowedTools "Bash,Read,Write" &   # фоновый процесс
claude -p "задача" --allowedTools "Bash,Read,Write" &   # ещё один
wait                                                      # ждём завершения
```

### Уровни параллелизации

1. **Bash background processes** — чистые скрипты без LLM overhead
2. **Субагенты** — встроены в Claude Code, параллельны, но не вложены
3. **Независимые claude -p** — полная изоляция, каждый "думает"
4. **Agent SDK** — программная оркестрация через Python/TypeScript

## Уроки

1. **Sandbox — это и защита, и клетка.** Безопасность sandbox'а Cowork защищает пользователя, но создаёт бутылочное горлышко для data-intensive задач. Всё, что проходит через контекст модели, подвержено ограничениям размера и потенциальному искажению.

2. **Правильный уровень абстракции.** Chrome MCP отлично подходит для интерактивной работы с веб-страницами. Но для batch-обработки 75 видео — это неправильный инструмент. Playwright на уровне ОС — правильный.

3. **Разделяй интеллект и исполнение.** LLM не должен передавать данные — он должен оркестрировать. Тяжёлая работа (HTTP-запросы, парсинг SRT, сохранение файлов) — задача детерминированных скриптов. LLM добавляет ценность там, где нужен "интеллект": генерация summary, обработка ошибок, принятие решений.

4. **Протоколируй опыт.** Без документации каждый следующий курс начинался бы с нуля. Протокол превращает разовый опыт в переиспользуемый актив.

5. **Cowork — для проектирования, Claude Code — для исполнения.** Cowork идеален для исследования (Chrome MCP, computer-use, интерактивная работа). Когда методика отлажена — переносим в Claude Code CLI для масштабного исполнения.
