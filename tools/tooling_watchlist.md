# Tooling Watchlist — Code & Agents

## Цель

Отслеживать развитие ключевых инструментов для кода и агентных систем и раз в неделю получать краткий, немаркетинговый отчёт: какие **новые фичи** и **кейсы использования** реально могут повлиять на мою работу.

## Стек инструментов

1. Claude Code / Cowork (Anthropic)  
   - Тип: код‑ассистент, IDE‑интеграции, агентный «коворкинг».  
   - Основные источники:
     - Публичные страницы и документация Anthropic.
     - Публичные X (Twitter)‑аккаунты Anthropic и команды.

2. Codex (OpenAI)  
   - Тип: инструменты OpenAI для кода и разработки.  
   - Источники:
     - Публичные страницы и документация OpenAI.
     - Публичные X‑аккаунты OpenAI и разработчиков, пишущих про Codex/кодовые модели.

3. Cursor  
   - Тип: AI‑IDE / код‑редактор с тесной интеграцией моделей.  
   - Источники:
     - Официальный сайт Cursor и их документация.
     - Публичные X‑аккаунты Cursor и команды.

4. Antigravity / Google Genie / AI Studio (Google)  
   - Тип: продукты Google для кода, агентов и AI‑инструментов разработки.  
   - Источники:
     - Публичные страницы и документация Google (AI Studio, Antigravity, Genie и родственные продукты).
     - Публичные X‑аккаунты Google Developers, Google DeepMind и релевантных команд.

5. Инструменты от xAI (релевантные коду и агентам)  
   - Тип: модели и инструменты xAI, применимые к задачам кодинга и агентов.  
   - Источники:
     - Публичные страницы и документация xAI.
     - Официальные X‑аккаунты xAI и ключевых инженеров.

## Что считать «событием»

### 1. Новые фичи

Считать значимыми событиями:

- Запуск или крупное обновление фич: новые возможности в IDE, новые режимы агента/коворка, поддержка дополнительных языков/фреймворков, интеграции (GitHub, Jira и т.п.), серьёзные изменения UX.  
- Существенное улучшение качества: заметный рост скорости/надёжности, улучшение кода в конкретных бенчмарках, новые способности (например, рефакторинг больших баз, сложные миграции).

### 2. Кейсы использования

Считать значимыми кейсами:

- Реальные истории пользователей, где:
  - есть пример задачи,
  - показано, как инструмент применили,
  - и есть результат: экономия времени, повышение качества, новый тип задач, который стал возможен.
- Кейсы от продвинутых пользователей/команд (особенно в инженерных/прод‑контекстах), желательно с кодом, скриншотами, цифрами.

## Что игнорировать

- Чистый маркетинг и хайп: общие заявления без примеров, метрик, демо или кода.  
- Повторяющиеся анонсы, где нет новых технических деталей по сравнению с прошлой неделей.  
- Обсуждения, не относящиеся к практическому использованию инструментов (политика, общие «AI рассуждения» и т.п.).

## Формат недельного отчёта

Каждый отчёт должен содержать:

1. **Executive summary (до 1 страницы)**  
   - 3–5 пунктов о том, какие изменения недели реально могут повлиять на мою работу.

2. **Блок «По инструментам»**  
   Для каждого инструмента из списка:
   - Краткий список новых фич (если были).
   - Краткий список новых кейсов (если были).
   - Оценка: полезно ли это мне прямо сейчас (да / нет / возможно позже) с пояснением в 1–2 предложения.

3. **Таблица сравнения**  
   Таблица с колонками:
   - Инструмент  
   - Новые фичи (кратко)  
   - Новые кейсы (кратко)  
   - Потенциальное влияние: низкое / среднее / высокое  
   - Нужны тесты на этой неделе: да / нет

4. **Рекомендации на неделю**  
   - Список не более чем из 3 конкретных действий: что именно протестировать, попробовать или поменять в своём рабочем процессе.  

## Частота и первый запуск

- Базовая частота: **раз в неделю, по понедельникам**.  
- **Особое правило для первого запуска:** сразу после загрузки этого файла и создания задачи Computer должен немедленно сформировать первый отчёт по текущему состоянию и последним изменениям (без ожидания недели).
