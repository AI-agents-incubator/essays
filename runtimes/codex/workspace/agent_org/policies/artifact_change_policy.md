# Artifact Change Policy

Purpose: control how artifacts evolve without uncontrolled drift.

Owner: `learning-agent`

Rules:
- Structural changes require a proposal in `evolution/change_proposals.md`.
- Approved changes must be recorded in `evolution/approved_changes.md`.
- Changes to charter or policies require `business-sponsor-interface` approval.
- Each change must reference a benchmark or audit finding.

Change workflow:
1. Add proposal with rationale and target artifacts.
2. Review by `engineering-manager`.
3. Approval logged in `evolution/approved_changes.md`.

Update rules:
- Proposed by `learning-agent`, approved by `business-sponsor-interface`.
