# Parallel Launch Protocol

> Версия файла: `v1.0`
> Дата версии: `2026-03-17`
> Тип документа: `operator protocol`

## Назначение

Этот документ нужен оператору, который запускает две независимые runtime-песочницы параллельно:

- `Codex`
- `Claude Code`

Обе песочницы уже подготовлены. Их не нужно дополнительно конфигурировать вручную. Нужно только открыть для каждой отдельный тред или отдельную рабочую сессию и передать стартовый prompt.

## Базовый принцип

Каждый агент работает автономно, но только внутри своей sandbox.

- `Codex` пишет только в `runtimes/codex/`
- `Claude Code` пишет только в `runtimes/claudecode/`

Они не должны:

- менять `core/`
- менять `comparison/`
- менять директорию другого runtime

## Как запускать

### 1. Откройте две независимые сессии

- одну сессию для `Codex`
- одну сессию для `Claude Code`

Лучше всего, если каждая сессия стартует из корня репозитория или из своей runtime-директории.

### 2. Дайте каждому агенту только один стартовый prompt

Не нужно отдельно пересказывать ТЗ.

Вся нормативная база уже лежит в:

- `AGENTS.md` для `Codex`
- `CLAUDE.md` для `Claude Code`
- `CURRENT_MISSION.md` для активного прогона

### 3. Не микроменеджьте

После старта агент должен:

- сам прочитать нужные документы;
- сам восстановить контекст;
- сам спланировать run;
- сам внести изменения в своей sandbox;
- сам оставить summary, evaluation и learning trace.

Человек вмешивается только если:

- агент явно запросил эскалацию;
- агент пытается выйти за write scope;
- агент вошёл в цикл без прогресса;
- агент не может принять решение из-за реально отсутствующего бизнес-требования.

## Что наблюдать во время прогона

Во время работы полезно смотреть не на каждое действие, а на несколько признаков:

- соблюдает ли агент write scope;
- создаёт ли он новые run-артефакты, а не переписывает историю хаотично;
- обновляет ли state layer осмысленно;
- оставляет ли evaluation trace;
- формирует ли следующий шаг, а не просто заканчивает “по факту”.

## Что считать хорошим запуском

Хороший запуск означает, что агент:

- стартовал из entrypoint без ручного сопровождения;
- сам нашёл текущую mission;
- выполнил run внутри своей sandbox;
- оставил run summary;
- оставил evaluation trace;
- обновил state layer и learning trace;
- сформулировал следующий run.

## Что делать после завершения

После завершения двух прогонов:

1. сравнить результаты двух runtime;
2. посмотреть, где различия structural, а где только stylistic;
3. перенести общие удачные решения в `core/`;
4. runtime-specific механизмы оставить в соответствующих sandbox.
