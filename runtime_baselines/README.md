# Runtime Baselines

> Версия файла: `v1.0`
> Дата версии: `2026-03-17`
> Тип документа: `baseline catalog`

## Зачем нужен этот каталог

Здесь лежат **базовые, версионируемые template-пакеты операционной системы агента**.

Идея простая:

- агент не должен стартовать "голым";
- до любого проектного запуска у него уже должен быть установлен базовый runtime layer;
- этот слой должен восстанавливаться из стандартного baseline-пакета;
- только после этого поверх него накладываются project-specific инструкции и активная mission.

Именно этого шага нам не хватало раньше.

## Что такое baseline

`Runtime baseline` — это не проектная задача и не текущий run.

Это **стандартный пакет метафайлов**, который задаёт:

- постоянные инструкции;
- базовые настройки автономности;
- default safety profile;
- стартовый набор ролей;
- стартовый набор skills;
- rules/hooks/policy layer, если runtime это поддерживает.

## Три уровня перед запуском

Полезно думать так:

1. `Runtime baseline`
2. `Project overlay`
3. `Active run`

То есть сначала восстанавливается baseline, потом добавляется конкретная проектная среда, и только потом стартует текущая миссия.

## Важное правило

Baseline-пакеты живут отдельно от `runtimes/`.

Это сделано специально, чтобы:

- не мешать живым автономным прогонам;
- не смешивать default template и активную песочницу;
- можно было безопасно обновлять baseline независимо от текущих run.
